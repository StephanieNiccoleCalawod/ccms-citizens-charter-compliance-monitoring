# Shared package consolidation

The standalone `ccms-shared-develop.zip` is the baseline. All five vendored copies were compared file by file before extraction. Archive names, SHA-256 hashes, original dependencies and scripts, environment references, and migration files are recorded in `source-inventory.json`.

| Copy | Differences from standalone | Resolution |
| --- | --- | --- |
| Core, Operations, Oversight | Runtime source and package exports identical. Vendors omit tests, README, lint config, CI and lockfile. | Keep standalone source and tests. |
| Frontend | Older `src/index.js` and `src/logs-client.js` omit `audit-name.js` export and `entity_name` in audit payloads; also lacks standalone tests/tooling. | Keep standalone audit naming and exports, consistent with the backend copies. Client navigation/role subpath exports remain unchanged. |
| Identity | Adds `get()` to memory and PostgreSQL rate-limit stores, and `consume=false` to `check()` for login lockout checks. Also lacks standalone tests/tooling. | Keep Identity's additive implementation and standalone test suite. Consuming checks retain their original semantics. |

There are no remaining vendor directories. Applications depend on `ccms-shared: "0.1.0"`, matching the local workspace version; npm links it locally. npm's `workspace:*` protocol is deliberately not used because npm workspaces use normal version ranges for sibling dependencies. No generated shared build is required: its exports point to ESM source.

Direct external dependencies were initially pinned to their respective archive lockfile versions. With the user’s approval, all six applications now use Next.js 16.4.5 and matching eslint-config-next 16.4.5 to address the security notice from the archived 16.4.0 builds. Other direct versions remain pinned to the archive resolutions. The frontend's automatic `agentUpgrade` configuration was removed to keep migration installs/startup from upgrading the framework. The root runner resolves Next.js separately from each workspace. Each Next.js configuration now explicitly sets the repository as its Turbopack and output tracing root so the shared workspace is visible. These options follow the [official Turbopack configuration](https://nextjs.org/docs/app/api-reference/config/next-config-js/turbopack) and [output tracing guidance](https://nextjs.org/docs/app/api-reference/config/next-config-js/output).

The deliberate shared runtime default change is `DB_SYNCHRONIZE=false` when unspecified. Explicit `db:sync`, `migrate`, test database creation, and bootstrap commands still request synchronization. All four application runtime data sources also explicitly set synchronization off; their administrative scripts retain explicit synchronization overrides. API handlers, authentication rules, database entities, schema ownership, migration SQL and service boundaries are preserved.

Runtime connections also disable TypeORM extension installation, which otherwise issues CREATE EXTENSION even with synchronization off. Explicit schema setup still enables both. Deployment-specific job tests now verify the manual endpoint inventory in `docs/local-jobs.json` and actual GET exports; Operations naming tests verify the root lockfile workspace entry/link. The original real-HTTP Core client test uses a one-second test-only deadline instead of 80ms, preserving its two-attempt assertion and the application’s unchanged five-second default. Test HTTP servers now stop listening before closing connections, following [Node.js HTTP shutdown guidance](https://nodejs.org/api/http.html#servercloseallconnections), to prevent a fixture teardown race.
